# 岛屿理解 Agent：实现与训练路线

## 产品输出

一次分析产生两层内容：

1. **个人分析报告**：综合结论在前，再用 3–5 个互不重复的主题形成完整画像。
2. **给岛主的话**：最后用一段温暖的第二人称文字收束。

每条解释必须在后台引用岛主实际选择或最终场景中的 evidence key。证据链和反向假设不在前台重复展示，但会用于服务端校验。后端会丢弃模型伪造的引用，并用数据库原文重新组装证据。报告中的 MBTI、OCEAN、依恋类型保持 `null`；岛屿设计没有完成这些测量。

## 当前推理链路

```text
岛屿设计与最终场景
  → 服务端生成不可篡改的观察记录
  → DeepSeek / 本地 Codex 生成结构化 JSON
  → 服务端校验解释、证据与禁用标签
  → 完整报告 + 给岛主的话
  → 岛主确认或修正
  → 只把确认后的内容写入长期记忆
```

生产环境可设置：

```bash
ISLAND_REFLECTION_PROVIDER=deepseek
ISLAND_ANALYSIS_API_KEY=...
ISLAND_ANALYSIS_MODEL=deepseek-v4-flash

# 为兼容旧配置也支持：
# DEEPSEEK_API_KEY=...
# DEEPSEEK_MODEL=...
```

密钥只放在服务端。模型返回空内容、超时、非 JSON、引用不存在的证据或输出心理诊断标签时，服务端使用原有的观察性文字兜底，不写入未经确认的记忆。

## 为什么暂不微调

第一阶段最重要的数据不是大量模型自生成报告，而是“岛的选择 → 初稿 → 用户确认/修正”。过早微调会把尚未验证的象征映射固化。先积累包含用户修改的去标识化样本，并建立一组人工审核的评测集。

评测至少包含：

- 证据覆盖：解释能否回到真实的岛屿选择。
- 越界率：是否擅自给出诊断、MBTI、依恋或数值人格分数。
- 另一种可能：是否避免把单一象征说成唯一答案。
- 用户认同与修改：接受、局部修改、完全否定分别记录。
- 文风：具体、温暖、不奉承、不替用户下结论。

## 后续训练框架

- **DSPy**：先用小规模已审核样本优化提示词和流水线，适合第一阶段。
- **LlamaFactory**：有足够的确认/修正对后，用 LoRA/QLoRA 做 SFT；再把“接受稿 / 修改前稿”整理成偏好对做 DPO。
- **TRL**：需要自定义训练循环、损失函数和细粒度评测时使用。
- **Langfuse**：记录模型版本、提示词、时延、花费、用户反馈和离线评测；可以自托管。

不以“累计多少条”作为唯一开训条件。只有当独立评测集稳定、修正原因已经收敛、隐私处理完成，并且提示词优化仍不能解决重复错误时，才进入微调。

## “美梦成真岛”应怎样写

可以保留“瀑布、水网、游泳、三只独角兽、没有房子、随地而坐、来者可以实现愿望”之间的诗意联系，但要把报告写成假设：

- “水网与在其中游动，也许让流动和沉浸成为这座岛的生活方式。”
- “向来访者开放愿望，可能表达了对相遇和给予的想象；也可能只是她在设计一条童话规则。”
- “没有房子、随地而坐，像是在削弱室内外的界线；另一种可能是她单纯不喜欢建筑占据风景。”

不能从这些选择直接得出“ENFP”“焦虑型依恋”“尽责性 0.20”或“情绪稳定性 0.45”。这些是需要独立、有效测量的构念。
